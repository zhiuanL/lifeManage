LifeOS 是一个单人、本地优先的桌面生活操作系统。它先帮助你看见生活状态，
再逐步管理生活中的对象。

## 功能

当前提供 M0-M4 的基础流程、M5 的事实分析与上下文导出、M6 的
搜索、模板、版本历史和桌面备份恢复，以及 M7 的个人记录与资源能力：

- 中文化生活版图首页与领域上下文页。
- 日历默认议程，支持周 / 月视图、领域和类型筛选，汇总行动、目标截止、习惯周安排及实际记录、复盘和事件；可返回源记录及编辑行动。
- 中文设置中心集中提供管理入口和暖色浅色、深黑、蓝灰深色、暖色深色四主题；保留旧林荫偏好。提供领域显示 / 隐藏和固定位置排序、模块启用开关；停用收起日常导航，不删除记录。六步初始化可稍后继续；首页按生活状态、当前关注、领域景观及方向 / 注意 / 趋势 / 复盘组织事实。
- 全新空间预置事业、成长、健康、关系、财务五个空白推荐领域；已有空间不会被自动补入，
  可在人生景观中按需勾选“添加推荐领域”。领域仍可创建、编辑、暂停和归档；
  可按需创建领域指标、记录每日数值、
  更正记录并归档指标，关联多个领域的指标只保存一份。
- 行动可选记录实际结果、投入分钟、收获、问题、未完成原因与后续调整，以及触发情境、执行动作与备用方案。默认折叠，快捷完成不要求填写；零分钟与留空分别保留，重新编辑可清空。反馈变更前的快照保留为中文只读历史，清空后仍可追溯。
- 中文复盘支持日、周、月、季、年五周期、草稿 / 已完成、分区自由书写；月 / 季 / 年可切换叙事模式。保存后编辑沿用当时模板快照，旧回顾保持未分类与原内容；列表支持周期、状态和领域筛选，正文默认折叠。
  周 / 月 / 季 / 年新建草稿按日期和领域汇总直接下级复盘、行动、当前目标快照、指标和问题；周复盘纳入计划变更。可修改、清空或补充，手工内容与显式删除不被重新填入；已保存记录仅在点击“汇总事实”时读取，不自动改写。缺少日常数据仍可书写。
  季度纳入当前资源缺口、目标滚动候选和长期方向；年度纳入实际事件、重大决策、技能当前快照与长期方向，明确区分事实和待确认调整，不推断年度增长量。
  复盘可显式选择关联目标和问题；导出只使用直接关联并遵守隐私范围，完整备份支持保留原模板、答案和关联。
- 目标、行动、日历和轻量回顾。目标可选择上级，并添加关键结果、里程碑、
  量化结果或探索节点，调整当前值、目标值与权重；进度自动加权计算，修改前
  的进度项保留历史。无进度项时按直属子目标与行动的贡献权重汇总，默认权重为 1，事实不足不显示百分比。
  权重可在折叠设置中修改，修改前版本保留历史，不补造计划或完成事实。
- 探索型目标默认不显示百分比，可在折叠的“进度设置”中开启；开启后沿用事实进度计算，
  关闭不删除进度项、行动或完成事实。模板设置仅在创建时复制，不改写已有目标。
- 目标可选年度、季度、阶段、月度周期，并关联愿景与长期方向；新年度目标须关联方向。
  旧目标保留未分类，已关联的归档方向仍保留；修改周期或方向前的版本纳入历史。
- 目标可设置高、中、低优先级，默认中；编辑时保留原值，修改前版本纳入中文历史。
- 目标可在折叠区关联支持、依赖、冲突、相关关系；只读预览显示双向关系并可跳转。
  冲突及相关不重复存储；关系修改保留历史，并纳入桌面备份恢复。
- 目标支持候选、进行中、暂停、已完成、放弃、归档六种状态；暂停与放弃记录原因，
  状态变更前的原因与完成事实保留历史。归档已完成目标保留完成时间，恢复进行中
  不保留当前完成标记，也不会删除历史。旧暂停记录不被强行补写原因。
- 目标与行动页可分别按状态筛选，默认收起已完成、放弃及归档目标和已完成行动；
  记录仍可查看、编辑及恢复。领域筛选同时保留，列表筛选不影响完整事实进度，
  搜索／历史直达仍能定位已结束记录。
- 点击目标名称打开只读详情预览，查看上级、状态、优先级、日期、进度、下级与关联行动；
  关闭后返回行动清单，键盘焦点恢复。可进入完整详情页，按区块就地编辑，默认保持阅读状态。
- 全局快速记录与收集箱整理，可经确认转入目标、行动、回顾、问题、决策、人物或事件。
- 问题跟踪与重大决策记录，可从生活领域进入对应上下文。
- 中文分析页：按周查看行动当前排期、实际完成、目标与回顾，并查看有来源的
  行动改期、完成时安排对照，以及可核验的行动到期完成率；可按领域查看单项
  指标的实际记录趋势，并返回原始记录。失效的领域或目标筛选会明确提示。
- 注意事项：目标日期、关联行动静止、反复问题、近 28 天多次改期及指标连续
  数值下降；阈值可调整，提示均附带记录依据，不判断数值变化的好坏。
- 手动上下文导出：六种场景模板，时间／领域／目标／隐私筛选、预览确认，
  Markdown／纯文本／JSON。改期记录继承行动的隐私等级，指标记录继承指标定义
  的隐私等级；领域及周／月复盘场景可按实际记录日期纳入指标事实。不调用 AI 接口。
  人生导航纳入目标分析、重大决策和领域场景，默认私密；领域或目标范围仅包含由范围内、
  隐私可见目标关联的长期方向，不带出无关导航。日期按导航更新时间筛选，变更筛选后重新确认。
  目标分析与重大决策可纳入显式关联资源需求及人物；资源使用独立隐私等级，
  日期、类型与字段筛选不带出被隐藏引用。新资源默认私密，旧资源升级时保留所属目标 / 决策的原等级，此后互不影响。能力成长可纳入目标、领域与周期复盘；重大决策仅纳入可见资源显式引用的能力，
  能力隐私独立维护，高度敏感记录始终排除，旧自定义模板不被自动改写。
- 全局搜索已开放的领域、指标、目标、行动、回顾、问题、决策、习惯、人物、
  事件、能力、人生导航与收集箱记录；
  支持关键词、类型、日期、状态和生活领域筛选；人生导航结果直达具体记录，归档记录只读查看。
- 模板中心可复制、创建、编辑领域／目标／回顾／问题／决策／习惯／上下文导出模板；
  SMART 预置里程碑与量化结果，OKR 预置关键结果，可修改初始进度项与权重；从模板
  中心使用时带入新建目标表单，目标、领域关联及初始项在同一事务保存，失败回滚。
  复盘提供日 / 周 / 月 / 季 / 年预置，自定义副本支持周期、字段名称、默认内容、增删与排序；保存时复制模板版本，修改模板不影响旧复盘。
  导出模板支持分段和字段排序。模板修改不会改写已保存对象；习惯模板可用于新建习惯。
- 习惯支持多领域关联、每周频率、轻量打卡、补记与撤销、归档及可选的情境／阻碍记录；
  完成率和连续情况仅基于已有记录的完整周计算，不催补断档。
- 习惯页可展开“周期统计”选择起止日期，查看周期完成率；仅计入已结束且有记录的完整周，
  每周完成次数不超过期望次数，无可用事实显示“暂无”。选择仅在当前页面保留；目标可单独保存关联习惯的统计周期。
- 目标的折叠“进度设置”可选择习惯型，关联多个习惯并保存各自的周期、频率和权重；
  按已有完整周事实加权，任一关联缺少可用事实时保持未知。可展开查看分项依据，
  配置修改保留历史，并纳入桌面备份与恢复；切换方式不删除原习惯打卡。
- 人物记录已确认的关系信息与联系状态；重要事件可关联人物、目标和多个领域。
  人生时间线还可查看已有的目标完成、重大决策与回顾节点。
- 能力成长记录当前和期望水平、学习路径、实践与复盘。资源总览引用现有能力、
  人物、目标行动与领域状态记录，可按目标或决策记录具体资源需求，不推测财务余额。
  决策可从“资源缺口”入口查看引用的源需求，统计已记录、已具备与待补齐，并筛选待补齐项；
  勾选直接更新源事实，没有记录不代表资源充足或不足。
- 月度／季度系统成效评估按五个结果保存主观回看，并附本期可查事实及来源；
  不把记录数量当作改善程度，也不生成系统总分。
- 人生导航、目标、回顾、问题与决策的修改前版本可从对应记录进入查看；旧记录不会虚构历史。
- 桌面版可下载完整应用级 JSON 备份，并在文件结构预检后确认替换恢复；
  恢复前自动保存安全快照，数据库约束或关联校验失败会回滚。备份包含全部隐私
  等级、关联、历史、习惯打卡、人物、事件、能力、资源需求、系统评估和
  自定义模板，不加密，请自行妥善保管。当前源码的备份版本为 52，可恢复版本
  15 至 52 的 LifeOS 备份，不提供其他系统数据的自动迁移。
- 人生导航可记录使命、核心价值观、愿景与长期方向、个人原则；默认只读，按需新增、编辑、归档与恢复，不要求填写，也不参与打分。
- SQLite 迁移与本地数据持久化。
- 四种标准界面主题可持久化，旧主题偏好保持兼容。

### 安装后提示无法打开本地生活空间

请确认运行的是 `LifeOS_0.1.0_x64-preview-verified-setup.exe` 安装的版本。此前安装包缺少 SQLite 写入权限，
在首次初始化时会失败；修复版会显示实际错误原因。

Windows 数据库存放在 `%APPDATA%\com.lifeos.app\lifeos.db`（可在文件资源管理器
地址栏输入 `%APPDATA%\com.lifeos.app`）。若出现“旧版本地数据库不兼容”，
请退出 LifeOS，先把 `lifeos.db` 及同目录下可能存在的 `lifeos.db-wal`、
`lifeos.db-shm` 一起复制到安全位置。当前版本不支持自动导入此前采用不同
迁移表结构的旧数据库。确认备份完整后，若要先使用空白生活空间，可把原文件
移出应用数据目录，再重新打开；不要直接删除旧记录。安装／卸载本身不能
替代数据备份，也不要未经迁移计划修改应用标识。

## 运行命令

```powershell
pnpm test
pnpm lint
pnpm build
pnpm dev
pnpm tauri dev
cargo check --manifest-path src-tauri/Cargo.toml
pnpm tauri build --no-bundle --ci --no-sign
```

`pnpm dev` 打开浏览器预览（默认 `http://localhost:1420`），数据仅在当前进程的
内存中；需要在本机长期保存数据时使用 `pnpm tauri dev`。
如果 1420 已被占用，可为**浏览器预览**另选空闲端口（例如 1433）：

```powershell
pnpm dev --host 127.0.0.1 --port 1433 --strictPort
```

然后打开 `http://127.0.0.1:1433`；若该端口也被占用，继续更换 `--port` 的数值。
Tauri 桌面开发使用固定的 1420 端口；
运行桌面版前须让该端口空闲，不能直接套用浏览器预览的端口参数。

## 环境要求

- Node.js 与 pnpm
- Rust stable 工具链
- Windows 上的 Tauri 运行前置条件

运行 Rust 的真实迁移备份测试需 Node.js 24（测试从现有 TypeScript 迁移
生成隔离的临时数据库）；桌面应用运行不依赖此测试要求。

本地 Rust 工具链还需要 `rustfmt`，以便 Tauri 插件工具正常格式化：

```powershell
rustup component add rustfmt
```
