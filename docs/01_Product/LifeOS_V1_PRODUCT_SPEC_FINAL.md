# 1. 产品定位与成功标准

LifeOS
不是“把人生当项目管理”，也不是万能数据库。它是一个单人、长期、本地优先的人生运行系统：帮助用户看清当前状态，把长期方向转化为目标与行动，通过周期复盘及时校准，并在重大问题与决策出现时提供足够的事实背景。

| **一句话定义：** 人生由用户主动管理；LifeOS 负责结构、事实、反馈与上下文；外部 AI 负责按需分析与建议。 |
|--------------------------------------------------------------------------------------------------------|

半年后判断系统是否有效，优先看五个结果：对当前人生状态更清楚；目标与行动联系更清楚；复盘更规律；重大决策更有依据；问题能更早被发现。

明确反设计目标：不能因为功能多而让维护负担过重；不能把人生过度量化成评分；不能为了管理人生而花大量时间管理系统。日常维护预算为
5–10 分钟，允许断档；周/月复盘承担主要深度工作。

# 2. 科学设计依据

| **依据**                     | **研究启示**                                                                   | **在 LifeOS 中的落地**                                                    |
|------------------------------|--------------------------------------------------------------------------------|---------------------------------------------------------------------------|
| 自我决定理论（SDT）          | 持续动力与良好功能更依赖自主性、胜任感、关系感，而非外部控制。                 | 人生导航、可自定义领域/模板、用户最终确认，不让系统替用户决定。           |
| 目标设定理论                 | 明确且具有挑战性的目标通常比模糊“尽力而为”更能促进绩效；反馈与承诺是重要条件。 | 多类型目标模板、层级目标、自动进度、周期反馈，而非只做愿望清单。          |
| 实施意图（If–Then Planning） | 把“想做”具体化为“何时/何地/遇到什么情境就做什么”，能缩小意图—行动差距。        | 行动可选“触发条件/备用方案”字段，尤其适用于关键行动和习惯。               |
| 进展监测与反馈               | 实验元分析显示，提高目标进展监测频率能促进目标达成。                           | 周/月/季复盘、计划 vs 实际、目标停滞提示、趋势图。                        |
| 习惯形成研究                 | 习惯依赖稳定情境中的重复，形成速度个体差异很大。                               | 习惯独立于普通行动，重点记录情境、重复、完成率，不追求“21 天”式固定神话。 |
| WHOQOL 的生活质量观          | 生活质量是个人在文化、价值、目标、期待背景下对自身处境的感知。                 | 人生领域和指标以推荐模板为起点，但允许用户完全自定义；评分不是唯一事实。  |
| 动态自我调节/多目标研究      | 现实中需要在多个目标间分配时间与资源，并根据反馈调整。                         | 上下结合计划、目标优先级、计划变更历史、资源缺口、暂停/放弃机制。         |

科学性在这里意味着：让系统采用经过研究支持的“机制”，而不是把任何单一框架包装成人生标准答案。复盘、评分、模板和提醒都应支持用户自主判断，而不是替代判断。

# 3. 总体架构：六个层次

| **层次**        | **作用**                                 | **主要对象**                                                     |
|-----------------|------------------------------------------|------------------------------------------------------------------|
| A. 人生导航层   | 回答“为什么、往哪里走、遵循什么”         | 使命（可选）、价值观（可选）、愿景/长期方向、个人原则            |
| B. 状态层       | 回答“我现在怎么样”                       | 人生领域、领域指标、每日状态、人物关系状态、重要事件             |
| C. 目标执行层   | 回答“我要推进什么、如何落地”             | 年度目标、阶段目标、月度重点、周/日行动、日历、习惯              |
| D. 反馈校准层   | 回答“发生了什么、要怎么调整”             | 日/周/月/季/年复盘、问题、计划变更、规则提示、统计趋势           |
| E. 决策与成长层 | 回答“如何做重大选择、积累什么能力与经验” | 重大决策、能力模型、目标经验、个人资源总览、人生时间线           |
| F. 系统支撑层   | 让系统可长期维护和扩展                   | Inbox、模板、搜索、版本历史、备份、导入导出、AI 上下文导出、设置 |

# 4. 最终信息架构：Life Landscape + Domain Context + Capability

LifeOS 最终采用“双层架构”：

- **理解层（Understanding Layer）**：人生景观、人生领域、当前阶段、状态、趋势、生活张力、长期期待。
- **管理层（Management Layer）**：目标/行动、习惯、复盘、问题、决策、人物、事件、能力、资源、日历、关注中心、Analytics、Inbox、模板、AI 上下文导出等。

核心关系：

> **Life Landscape → Domain Context Hub → Capability → Object**

其中：

> **领域是上下文，模块是能力。**

领域不是树状文件夹，也不拥有一套复制的模块。目标、问题、复盘、人物等模块是全局能力；从某个领域进入时，仅自动带入该领域上下文筛选。一个对象可以同时关联 0..N 个领域。

主导航保持克制，默认建议：

| **一级入口** | **默认内容** | **说明** |
|---|---|---|
| 人生景观 | 当前生活状态、主要领域、当前阶段、生活张力 | 首页主入口，先理解人生，不做任务 Dashboard。 |
| 目标与行动 | 全局目标/行动；从领域进入时自动按领域筛选 | 核心执行能力。 |
| 复盘 | 日/周/月/季/年 | 结构化复盘为主，深度复盘可进入叙事模式。 |
| 日历 | Agenda/Timeline 默认；Week/Month 辅助 | 不设计独立 Today 工作台。 |
| 关注中心 | 规则驱动的“值得关注”事实与证据 | 主页面保持安静。 |
| 更多 | Inbox、习惯、问题、决策、人物、事件、能力、资源、Analytics、时间线、模板、AI 导出、设置等 | 能力目录，不是第二套系统。 |

“更多”中的多数能力既可全局进入，也可从具体领域上下文进入。备份、主题、设置、数据导入导出等系统能力不要求关联领域。

# 5. 首页：Life Landscape 人生景观

首页不再采用“可配置 KPI 驾驶舱 / 卡片墙”作为主视觉，而采用 **Life Landscape**。

首页第一屏优先回答：

- 我现在整体处于怎样的生活状态？
- 我当前处于什么阶段？
- 哪些领域正在获得动能？
- 哪些领域正在变弱？
- 现在最重要的方向是什么？

默认信息顺序：

1. 当前生活状态
2. 当前阶段 / 当前周期 / 当前重心
3. 关键方向、关键目标与近期行动
4. 低干扰“值得关注”摘要
5. 最近趋势
6. 最近 / 下一次复盘入口

首页中的主要人生领域是可点击节点。点击例如“健康”，进入健康领域上下文枢纽；在那里继续进入健康相关目标、习惯、复盘、问题、决策、人物、事件、资源和 Analytics。

首页允许有限的上下文式定制（显示/隐藏、轻量排序等），但不能重新退化为自由拼装 Dashboard。设计重点是保持人生景观与信息层级稳定。

# 6. 人生导航与人生领域

## 6.1 人生导航

“人生导航”整合使命（可选）、核心价值观（可选）、人生愿景/长期方向、个人原则/规则。它是低频战略层，不要求每日维护，也不参与机械打分。年度目标需要能够关联到长期方向；重大决策可以引用导航信息作为约束。

## 6.2 人生领域

系统提供推荐领域模板，但允许完全自定义。领域是一种长期生活语境，而不是项目目录。

每个领域至少包含：
- 当前状态
- 满意度 / 可选评分
- 长期期待
- 当前问题
- 活跃目标
- 近期行动
- 习惯
- 复盘记录
- 趋势
- 重要人物 / 事件
- 资源与 Analytics 入口

评分体系完全可自定义，文字状态与定量指标并存。每日状态指标采用推荐 + 自定义，并可关联 0..N 个人生领域。系统可以展示同期趋势，但不得把相关性包装成因果关系。

### 6.2.1 新增与管理领域

人生景观中直接提供低强调的“＋ 添加领域”入口，而不是只放在设置中。

首次创建仅要求：
- 领域名称
- 图形 / 颜色身份
- 长期期待
- 是否启用

保存后立即：
1. 加入人生景观；
2. 自动拥有领域上下文枢纽；
3. 自动获得现有通用管理能力；
4. 不复制目标、复盘、问题等模块。

领域支持改名、排序、景观位置调整、改色、暂停和归档。默认不通过物理删除破坏历史关系。

### 6.2.2 领域与模块的关联

目标、行动、习惯、复盘、问题、决策、人物、事件、能力、资源等对象允许与 0..N 个领域关联。

例如：
- 一个目标可同时属于“事业 + 成长”；
- 一个人物可同时关联“关系 + 事业”；
- 一个问题可同时影响“健康 + 事业”。

从领域进入模块时自动带入领域筛选；用户可清除筛选返回全局模块视图。领域是上下文，不是刚性父级。

# 7. 目标与行动系统

核心层级为：人生愿景/长期方向 → 年度目标 → 季度/阶段目标 → 月度重点 →
周行动 →
每日行动。规划采用“上下结合”：既可自上而下拆解，也允许现实中新出现的问题、机会和事件自下而上进入，再决定是否调整上层目标。

| **能力** | **设计**                                                                    |
|----------|-----------------------------------------------------------------------------|
| 目标模板 | 提供 SMART、OKR、习惯型、探索型等模板；用户可复制和修改字段。               |
| 进度计算 | 按目标模板使用默认算法，并允许调整下级权重；上级进度由子目标/行动自动汇总。 |
| 优先级   | 仅高 / 中 / 低三档，避免复杂评分。                                          |
| 生命周期 | 候选、进行中、暂停、完成、放弃、归档；暂停/放弃记录原因，保留历史。         |
| 目标关系 | 支持“支持 / 依赖 / 冲突 / 相关”轻量关系；V1 不做复杂关系图谱。              |
| 独立行动 | 允许行动不关联目标，避免为了结构完整而强行归类。                            |
| 行动反馈 | 完成状态、实际结果、投入时间（可选）、收获、问题、未完成原因、后续调整。    |
| 计划变更 | 保留原计划、调整后计划、调整原因、受影响对象、实际结果，并做基础统计。      |

关键行动可选增加“实施意图”字段：触发情境、执行动作、备用方案。它不是强制填写，避免增加日常负担。

# 8. 日历与习惯

LifeOS
内置基础日历为主，服务于行动、截止日期、周期计划、习惯安排、复盘节点和重要事件，不追求取代通用日历软件。

习惯独立于普通行动管理。平时采用轻量打卡，记录频率、完成率、连续情况和稳定情境；需要时进入深度分析，记录触发条件、阻碍因素与调整策略。

# 9. 复盘中心：系统的主要使用场景

复盘采用“结构化字段 +
自由书写”混合模式。下级数据自动汇总生成上级复盘草稿，用户可以修改、删除、补充；自动汇总基于规则和结构化数据，不依赖
AI。

| **周期** | **核心职责**       | **典型自动带出**                                               |
|----------|--------------------|----------------------------------------------------------------|
| 每日     | 执行反馈与次日微调 | 完成/未完成、原因、今日状态、收获、明日调整、目标是否需调整。  |
| 每周     | 系统级校准         | 本周执行、目标进度、反复问题、计划变更、下周重点。             |
| 每月     | 趋势与重点调整     | 各周结论、领域状态趋势、月度重点完成情况、问题演化。           |
| 季度     | 阶段目标与方向校准 | 阶段目标、领域状态、资源缺口、目标滚动。                       |
| 年度     | 长期方向与年度结果 | 年度目标、重要事件、重大决策、能力成长、领域变化、下一年方向。 |

允许日常断档。系统不因漏填一天制造“失败感”，而是在周/月复盘时把可用数据汇总出来，用户可以补充缺失背景。

# 10. Inbox：统一低成本入口

所有不确定归属的信息先进入统一
Inbox，包括想法、灵感、问题、事件、资料线索、待办、目标候选、决策议题。用户无需在记录当下先完成分类。

Inbox 整理采用三层：系统规则推荐 → 可选 AI 上下文导出 →
用户确认。系统可根据日期、关键词、已有对象匹配等给出初步分类，但不自动改动正式数据。

# 11. 问题、决策、人物、能力、资源与时间线

| **模块**   | **定位**                           | **关键设计**                                                                              |
|------------|------------------------------------|-------------------------------------------------------------------------------------------|
| 问题管理   | 长期追踪反复问题                   | 问题描述、首次发现、关联领域/目标、出现次数、原因假设、尝试方案、状态、后续复盘。         |
| 决策       | 普通决策轻量记录，重大决策升级建档 | 背景、选项、约束、风险、机会成本、可逆性、导航/目标关联、最终选择、理由、后续结果与复盘。 |
| 人物关系   | 从个人视角维护重要关系             | 基本信息、关系类型、生日/重要日期、共同经历、重要事件、最近联系、关系状态、备注。         |
| 能力成长   | 管理“我会什么、正在提升什么”       | 当前水平、目标水平、学习路径、相关目标、练习/成果、复盘。                                 |
| 个人资源   | 跨模块聚合 + 缺口分析              | 引用时间、精力、能力、人物、财务、工具等信息；重点回答“目标需要什么、当前缺什么”。        |
| 人生时间线 | 长期成长档案                       | 重要事件、目标变化、阶段成果、关键决策、领域变化、关系变化、复盘节点。                    |

# 12. 规则驱动的“值得关注”机制

LifeOS 可以主动发现值得关注的事实，但不擅自解释原因。示例：目标连续 4
周无进展、同类未完成原因反复出现、某领域状态持续下降、习惯完成率明显下滑、计划频繁被临时任务打断、资源长期不足。

提醒采用弱提醒策略。默认只提醒重要节点；系统健康检查可单独查看，不将普通异常转化为持续弹窗。

# 13. AI 上下文导出中心

LifeOS 不直接接入 AI。所有 AI
能力统一表现为“场景化上下文导出”：底层共用筛选与聚合引擎，上层使用不同模板。用户可以修改系统预设模板的字段、顺序和包含范围。

| **导出场景** | **默认上下文结构**                                                                             |
|--------------|------------------------------------------------------------------------------------------------|
| 目标分析     | 目标背景、上层方向、进度、关键行动、阻塞点、资源缺口、历史调整、复盘摘要、希望 AI 回答的问题。 |
| 周/月/季复盘 | 执行结果、未完成原因、状态变化、反复问题、计划变更、重点目标、下一周期议题。                   |
| 人生领域分析 | 领域现状、满意度/指标趋势、长期期望、问题、关联目标、近期行动、相关状态指标。                  |
| 重大决策     | 决策问题、选项、约束、人生导航、相关领域/目标、资源、风险、机会成本、历史相似决策。            |
| 问题诊断     | 问题描述、频率、触发条件、相关领域/目标、尝试方案、结果、历史类似问题。                        |
| Inbox 整理   | 待分类信息、已有领域/目标/人物/问题摘要、候选分类、希望 AI 判断的事项。                        |

导出格式建议同时支持 Markdown、纯文本和
JSON。导出前显示“将包含哪些信息”，并允许按时间、领域、目标、对象、隐私级别过滤。

# 14. 模板、搜索、版本、备份与设置

模板系统覆盖目标、复盘、领域、决策、问题、习惯和 AI
上下文导出。系统提供专业默认模板，用户可以复制、修改、创建；模板变化不影响历史数据。

全局搜索覆盖目标、行动、复盘、问题、人物、事件、领域等，并支持按时间、类型、领域、状态筛选。关键对象保留版本历史：目标调整、复盘补充、问题演化、重大决策背景等。

数据本地优先。V1
支持手动备份、恢复、系统自身数据导入/导出；历史旧数据迁移不作为重点，从零开始使用，有价值的旧内容手动补录。隐私字段支持普通
/ 私密 / 高度敏感分级，并在 AI 导出时过滤；应用锁与数据库加密暂不进入
V1。

设置中心集中管理人生领域、身份角色、人生导航、目标体系、复盘模板、人生景观的有限显示偏好、提醒规则、启用模块、主题、AI
导出模板。首次使用采用“推荐模板 + 引导式初始化”。

# 15. 日常运行流程与时间预算

| **频率** | **建议动作**                                             | **预算**          |
|----------|----------------------------------------------------------|-------------------|
| 日常     | 快速记录 Inbox；必要时更新行动；晚间做简短日复盘。       | 5–10 分钟，可断档 |
| 每周     | 系统汇总 → 目标/行动检查 → 计划变更与问题 → 下周重点。   | 30–60 分钟        |
| 每月     | 领域状态与趋势 → 月度重点 → 问题与资源 → 下月调整。      | 45–90 分钟        |
| 季度     | 阶段目标、资源、重大问题、方向校准、目标滚动。           | 1–2 小时          |
| 年度     | 年度结果、重要事件、决策、能力、领域变化、下一年度目标。 | 2–4 小时          |

系统应优先通过自动汇总减少重复填写。日常数据可以不完整，周/月复盘承担“补上下文、做判断”的工作。

# 17. 核心数据模型原则

LifeOS 采用“核心层级 +
多维关联”而不是单一树。目标可以同时关联人生领域、身份角色、问题、人物、资源、事件；行动可独立存在，也可关联一个或多个上层对象。所有关联都应尽量做到可选，避免为了结构完整而增加维护负担。

| **关键架构原则：** 能从其他模块引用的数据，不重复维护第二份。资源总览、分析、AI 导出都应以引用和聚合为主。 |
|------------------------------------------------------------------------------------------------------------|

# 18. 产品验收标准

首个可长期使用版本应满足以下验收逻辑：用户可以在不超过 10
分钟的日常维护下持续记录；能从愿景/长期方向追踪到年度目标和当前行动；周/月复盘能自动汇总事实并允许修改；系统可以主动提示停滞与反复问题；重大决策能形成完整背景；任何需要深入分析的场景都能导出高质量上下文；本地数据可安全备份和恢复。

每月/季度提供“系统成效评估”，检查 LifeOS
是否让用户更清楚状态、目标—行动更一致、复盘更规律、决策更有依据、问题更早被发现。若某功能长期没有贡献，应允许关闭，而不是因为“已经开发”就强迫使用。
