# LifeOS V1 — 最终 UI/UX 设计规范

## 1. 产品定位

LifeOS 是单用户、长期使用、Local-first 的个人 Life Operating System。

它不是：
- 项目管理工具
- Todo List
- 企业后台
- KPI Dashboard
- CRM
- BI 报表系统
- 日记软件

核心目标是：

> 先帮助用户理解自己当前处于怎样的人生状态与阶段，再在需要时进入具体管理能力。

因此 UI 必须长期维持“理解人生”优先于“管理对象”的认知模型。

---

## 2. 核心信息架构：双层模型

### 2.1 理解层（Understanding Layer）

用于理解人生，不以对象管理为主。

包括：
- 人生景观（Life Landscape）
- 人生领域（Life Domains）
- 当前阶段 / 当前周期
- 生活状态
- 生活张力
- 趋势
- 长期方向 / 长期期待
- 高层复盘语境

理解层回答：
- 我现在怎么样？
- 我正处在人生的什么阶段？
- 哪些领域正在获得动能？
- 哪些领域正在变弱？
- 现在真正重要的是什么？

### 2.2 管理层（Management Layer）

用于精确管理具体对象。

包括：
- 目标与行动
- 习惯
- 复盘
- 问题
- 决策
- 人物
- 重要事件 / 里程碑
- 能力成长
- 个人资源
- 日历
- 关注中心
- Analytics
- Inbox
- 模板
- AI 上下文导出
- 人生时间线
- 系统健康
- 全局搜索 / 命令
- 备份 / 恢复
- 设置与个人配置

理解层与管理层不是两个孤立系统，而是连续导航关系。

---

## 3. Life Landscape：LifeOS 的主视觉母题

首页采用“人生景观”而不是 Dashboard。

首页中的主要人生领域可直接点击，例如：
- 事业
- 健康
- 成长
- 关系
- 财务
- 用户自定义领域

每个领域以视觉节点存在于人生景观中。

首页不应该默认呈现大量表格、卡片、KPI、待办和进度。

---

## 4. 首页信息层级

首页顺序固定为：

1. 当前生活状态
2. 当前阶段 / 当前周期 / 当前重心
3. 关键方向 / 关键目标与近期行动
4. 低打扰“值得关注”摘要
5. 最近趋势
6. 最近 / 下一次复盘入口

首页第一屏必须优先回答“我现在处于怎样的生活状态”，而不是“我今天还有多少任务”。

---

## 5. 人生领域是上下文枢纽

这是最终信息架构的关键原则：

> 领域是上下文，模块是能力。

例如：

人生景观
→ 健康
→ 健康领域上下文
→ 健康相关目标 / 习惯 / 复盘 / 问题 / 决策 / 人物 / 事件 / 资源 / Analytics

从领域进入模块时：
- 自动带入该领域上下文
- 默认只展示相关对象
- 用户可清除领域筛选，返回模块全局视图
- 领域不是刚性文件夹，不限制对象只能属于一个领域

对象允许关联多个领域，例如：
- 一个目标可同时关联事业 + 成长
- 一个人物可同时关联关系 + 事业
- 一个问题可同时关联健康 + 事业

禁止把领域做成传统树状项目目录。

---

## 6. 新增领域

首页人生景观必须提供低强调的：

> ＋ 添加领域

新增流程采用轻量侧边 Sheet / 浮层。

首次创建只要求：
- 领域名称
- 领域颜色 / 图形身份
- 长期期待
- 是否启用

保存后：
1. 立即加入人生景观
2. 自动创建领域上下文枢纽
3. 自动获得所有通用管理能力
4. 不为新领域复制一套模块

领域管理支持：
- 新增
- 改名
- 调整顺序
- 调整景观位置
- 调整颜色
- 暂停
- 归档

默认不提供破坏性“直接删除历史”。

归档领域后，历史关联仍保留。

---

## 7. More 的定位

“更多”不是另一套系统，而是：

> LifeOS 能力目录

其中能力可全局进入，也可从领域上下文进入。

可关联领域的能力：
- 目标
- 行动
- 习惯
- 复盘
- 问题
- 决策
- 人物
- 事件
- 能力成长
- 资源
- Analytics
- 人生时间线
- AI 上下文导出

不强制关联领域的系统能力：
- 设置
- 备份 / 恢复
- 主题
- 数据导入 / 导出
- 部分系统健康功能

Inbox 为全局入口，但整理后可关联一个或多个领域。

---

## 8. 全局搜索 / 命令

搜索框不能完全隐藏。

采用：
- 平时弱显式
- 低对比
- 始终可发现
- Hover / Focus 时增强
- Ctrl/Cmd + K 快速打开
- 输入 “/” 或动作词后逐步进入命令模式

原则：
- 新用户把它当普通搜索即可
- 熟练用户逐渐发现命令能力
- 不要求用户先学命令语法

---

## 9. 快速记录

全局 “+” 打开底部 Composer。

规则：
- 保留当前页面上下文
- 点击后立即可输入
- 不要求先分类
- 默认保存到 Inbox
- 后续再转换成目标 / 行动 / 问题 / 事件 / 人物 / 决策 / 其他对象

不能把快速记录入口做成复杂命令面板。

---

## 10. 导航

左侧导航默认极简。

建议默认：
- 人生景观
- 目标
- 复盘
- 日历
- 关注中心
- 更多

人生领域不必永久展开在主导航中，因为它们主要从人生景观进入。

支持：
- 默认收起
- 当前模块二级导航
- 常用能力固定到侧栏
- 更多模块按需访问

---

## 11. 目标与行动

目标层级：
- 人生愿景 / 长期方向
- 年度
- 季度 / 阶段
- 月度重点
- 周行动
- 日行动

目标模板：
- SMART
- OKR
- 习惯型
- 探索型
- 用户自定义

生命周期：
候选 → 活跃 → 暂停 → 完成 → 归档 → 放弃

关系：
- supports
- depends on
- conflicts with
- related

主页面：
- 目标列表
- 点击目标打开右侧只读预览
- 完整页用于深度管理

右侧详情层必须保持只读。

完整详情页：
- 默认阅读状态
- 分区就地编辑
- 不切换成整页表单模式

---

## 12. 复盘

支持：
- 日
- 周
- 月
- 季
- 年

默认：
- 结构化复盘
- 每个区块内可自由书写
- 月 / 季 / 年支持更沉浸的叙事模式

上级复盘自动聚合下级事实形成草稿，由用户编辑。

---

## 13. 人生领域页面

领域页面属于理解层。

默认显示：
- 当前状态
- 长期期待
- 满意度
- 当前问题
- 活跃目标
- 最近行动
- 习惯
- 复盘
- 趋势
- 重要人物 / 事件
- 资源
- Analytics 入口

主视图：
- 领域摘要
- 趋势
- 相关能力入口

生活轮 / 雷达：
- 仅作为辅助摘要
- 不作为唯一界面
- 不暗示人生能被一个分数完整描述

---

## 14. 日历

内置 LifeOS Calendar。

默认视图：
- Timeline / Agenda

辅助视图：
- Week
- Month

显示：
- 行动
- 时间
- 截止日期
- 周期计划
- 习惯
- 复盘
- 重要事件

不设计独立 Today 工作台。

---

## 15. 关注中心

使用独立 Attention Center。

主页面保持安静。

可触发：
- 目标停滞
- 重复未完成
- 领域状态下降
- 习惯下降
- 计划扰动
- 资源缺口
- 复盘到期
- 重要事件

默认显示：
- 简短事实

展开后：
- 规则
- 数据点
- 基线
- 时间范围
- 来源记录

禁止自动输出：
- 因果推断
- 人格判断
- 人生建议

需要深度分析时通过 AI Context Export 交给外部模型。

---

## 16. 数据可视化

采用混合型。

普通页面：
- 柔和
- 生活感
- 低饱和
- sparklines
- 趋势
- 尽量少刻度

Hover / 展开 / 深入后：
- 精确数值
- 基线
- 来源记录

Analytics：
- 精确刻度
- 周期比较
- 过滤器
- 原始证据
- 跨模块分析

禁止为了“科学感”而过度量化人生。

---

## 17. 多主题

LifeOS V1 支持至少：

1. Warm Light — 默认
2. Deep Black
3. Blue Gray Dark
4. Warm Dark

主题可改变：
- 背景
- 表面
- 对比度
- 材质
- 环境色

主题不可改变：
- 模块身份
- 信息层级
- 功能结构

固定模块色系：
- Life / Landscape：蓝紫
- Goal：低饱和绿色
- Review：暖杏
- Attention：紫灰
- Calendar：灰紫

未来允许独立个人 Accent Color，但不得覆盖模块身份色。

---

## 18. 卡片与容器

默认采用弱容器布局。

原则：
- Card 只用于强调
- 不是所有内容都必须放 Card
- 多使用留白、排版、分割线、对齐形成层级
- 避免 Card Everywhere

---

## 19. 排版

Sans-serif：
- 导航
- 数据
- 表单
- 管理操作
- 控件

Serif / Editorial：
- 人生景观主标题
- 反思内容
- 重要阶段描述
- 复盘中的叙事节点

---

## 20. 图形语言

主要采用：
- 一致的精致系统图标
- 抽象几何
- 低干扰环境图形
- 轻量动态

不采用：
- 大量人物插画
- 卡通
- 游戏化角色
- 装饰性插图堆叠

---

## 21. 动效

动效强度：平衡。

包括：
- 微交互
- 页面 / 详情连续过渡
- 人生景观少量 ambient motion

管理页避免过度动态。

必须支持 prefers-reduced-motion。

---

## 22. 初始化

首次启动采用推荐模板优先。

模板可初始化：
- 人生领域
- 目标结构
- 复盘模板
- 首页结构
- 提醒默认值
- 启用模块

一切后续可修改。

---

## 23. AI 边界

V1 不内置 AI Agent 直接改数据。

采用 AI Context Export。

支持按：
- 时间
- 领域
- 目标
- 对象类型
- 隐私等级

导出：
- 结构化事实
- 上下文
- 历史
- 关联对象
- 用户问题

外部 LLM 分析，用户决定，LifeOS 保存事实。

---

## 24. 技术方向

推荐：
- Tauri 2
- React
- TypeScript
- Vite
- SQLite
- Rust

原则：
- Local-first
- Windows 优先
- macOS 架构兼容
- 无强制云依赖
- 手动备份 / 导入 / 恢复

---

## 25. 最终验收问题

每个页面开发完必须检查：

1. 是否像 LifeOS，而不是项目管理软件？
2. 理解层是否先帮助用户理解人生？
3. 领域与模块是否真正形成连续上下文？
4. 是否存在 Card Everywhere？
5. 是否使用渐进披露？
6. 是否保持模块稳定身份？
7. 详情侧栏是否只读？
8. 完整页是否分区就地编辑？
9. 关注信息是否事实与推断分离？
10. 新增领域是否能自然加入系统而无需复制模块？
11. 多主题是否只改变主题，不改变信息结构？
12. 搜索是否弱显式但可发现？

不满足时必须返工，而不是仅换颜色。
